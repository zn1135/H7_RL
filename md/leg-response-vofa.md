# 普通 VOFA：单侧腿响应布局

普通 VOFA 的原通道内容已直接替换为单侧腿测试，没有新增遥测帧型或协议模式。传输仍由既有 `vofa_transport.requested` 选择 UART 或 H7 USB CDC，策略追踪仍由 `vofa_trace_requested` 进入，S2R 仍由 `s2r_diagnostic_requested` 进入，三者同口互斥规则不变。

**RL 指令输入（2026-09-30）**：此前版本只隔离输出，原指令范围仍为 `[0, 0, 0.20]`，所以摇杆／拨轮不会改变网络目标。按用户后续要求，本版在单腿测试开启时开放 `vx、yaw_rate、height`，通过原完整观测和历史进入网络推理；没有新增绕过网络的腿长／摆角 PID。关闭单腿测试后仍恢复原固定指令。现有模型是固定高度起立策略，开放输入仅证明可以向网络给不同指令，实际跟踪能力仍待台架；本次未更换或训练权重。

| 输入 | 指令范围（作者指定） | 网络当前观测 |
| --- | --- | --- |
| 右摇杆 Y | `vx`：−5～+5 m/s | `obs[6] = vx × 2` |
| 右摇杆 X | `yaw_rate`：−5～+5 rad/s，沿用既有输入符号 | `obs[7] = yaw_rate × 0.25` |
| 拨轮 | `height`：0.15～0.30 m，中位 0.225 m | `obs[8] = height × 5` |

高度是机身高度指令，不是直接指定虚拟腿长；第二个指令是偏航角速度，不是横移速度或腿摆角。当前模型没有独立腿摆角输入槽，左摇杆摆角没有接入。所有三项指令和其余实时状态组成 25 维观测，再更新 5 帧共 125 维历史；`RL_Policy_Run()` 调用现有 `ai_networkzn1_run()` 得到 6 维动作，沿用既有 RL 力矩执行层，最终仅选中腿出力。

用户确认沿用现有 RL 策略和拨轮高度指令，只隔离最终输出。这份测试固件上电默认 `leg_response_test.requested=1`、`vofa_leg_response_side=0`，即左腿单测；先保持左拨杆下位，执行任务在失能时将配置锁存到 `leg_response_test.active/side`，再左上／右中投入原 RL。无需每次手动写 requested=1。测右腿时在失能状态改 side 请求为 1；恢复双腿正常控制需失能时显式写 requested=0。VOFA 跟随锁存侧，采集传输开关不参与控制选择。RL 控制律、策略动作、拨轮映射、物理极性和零点不变。

测试开启后，只将选中腿的原 RL 力矩送到其前后髋，其余两个髋和两轮发送零力矩命令（不是断线或机械锁止）。原控制器输出保持不变，`rl_output_dm_cmd_nm[]` 和 `rl_output_wheel_cmd_nm[]` 记录过滤后的命令。使能中改测试开关或测试侧会将普通输出闭锁为零，改回也不解除，必须先失能再锁存。非法配置或映射同样零输出。测试开启时 LQR 挡不出力，关闭测试后恢复既有控制路径；JID1 独立台架路径保持原有许可与使能门控。

普通 VOFA 以约 500 Hz（`commTask` 的 1 ms 节拍二分频）记录一次；它与执行任务异步，记录的是采样时最新命令和当前几何，不保证一条记录对应一个独立控制周期。打包期间禁止任务切换，防止前后髋命令和发送状态混拍，串口发送在解锁后进行。

| 通道 | 字段 |
| --- | --- |
| ch0 | MCU 单调时间 ms |
| ch1 | 测试侧：`0=left`，`1=right` |
| ch2–3 | 前、后髋 `pos_zero_rad`，即固件的 `pos_rad + dm_zero` |
| ch4–5 | 由最近一次下发的前/后髋命令和当前雅可比反解的虚拟大腿／小腿力矩 Nm，仍为固件虚拟关节坐标系 |
| ch6–7 | `RL_Joint_Map()` 后的虚拟大腿／小腿位置 rad：以 RL zero 为零，未加入训练默认角 |
| ch8 | 实测虚拟腿长 m |
| ch9 | 有效位：bit0 闭链解算、bit1 RL 映射、bit2 虚拟力矩反解、bit3/4 前/后髋反馈可靠、bit5 最近一次四髋 CAN 命令全部入队成功 |

反馈可靠要求在线、无故障、位置有限、存在已解析 CAN 接收时间，且接收时间不晚于采样、年龄不超过 10 ms。任一髋不可靠或闭链解算无效时清空派生值，不复用旧解算。雅可比不可逆或 CAN 入队失败时 ch4–5 为零且 `ch9.bit2=0`；零值须连同有效位判断。零出力命令入队成功也可置 bit5，它不代表电机使能，更不证明力矩已经在电机内部生效。命令值未回算 MIT 量化误差；虚拟力矩不是反馈力矩。ch6–7 是 `RL_Joint_Map()` 的直接输出，不加也不减训练默认角；与 ch4–5 的坐标约定分别保留，不能直接混用为功率。

普通 JustFloat 为 10 个 float32 加帧尾（44 B）；500 Hz 约 **22 kB/s**，不再是原 32 通道方案的 66 kB/s。ch0 是整数毫秒转 float32，开机约 4.66 小时后不再保持每毫秒精确，短时测试应重新上电并单独录制。

## 台架操作

1. 固定机身、两轮离地，四髋及两轮保持接线与在线。左拨杆下位失能，确认 `robot_state.motor_enabled=0`，先设 `torque_output_enabled=0`。
2. 本测试固件默认左腿且 requested=1，失能后等待 `active=1`、`side=0`、`inhibited=0`。测右腿则失能时设置 `vofa_leg_response_side=1`。仅看单侧数据而不隔离控制时，须显式设置 requested=0；该修改不跨重启保存。
3. 保持失能并退出 JID1 的左上／右下许可挡位，停止 JID1 采样流。设置 `s2r_diagnostic_requested=0`、`vofa_trace_requested=0`、`vofa_transport.requested=0`，等 `vofa_transport.active=0` 后将 VOFA+ 接到 H7 USB CDC，选择 JustFloat、10 通道。UART8 回退为 requested=1、1152000 8N1。
4. 先零出力连续录制 30 秒，目标约 15000 帧、660000 字节原始载荷；检查时间递增、间隔通常约 2 ms、有效位、左右归属和静止腿长。这个速率是待实测目标，不是已验收结果。没有序号/CRC，时间间隔和字节数只能帮助检查吞吐，不能证明无丢帧或无损。
5. 零出力时先将左拨杆上、右拨杆中投入原 RL，确认 `rl_output_dm_cmd_nm[]` 与轮命令仍全零。改变右摇杆和拨轮，核对 `input_command.vx_cmd/yaw_cmd/height_cmd` 与 `rl_control.observation.obs[6..8]` 按上表变化、`rl_control.policy.run_ok` 持续增加，并查看 `action_state.a[0..5]`；这一步检查输入与推理链路。再次失能后将 `torque_output_enabled=1`，再左上／右中投入，先小幅改变指令并记录本侧实际响应。非测试侧两髋和两轮命令应始终为零；全部电机在线、IMU、两腿有效、动作就绪等原门控仍生效。
6. 结束时左拨杆下位失能。换侧或退出测试均在此时操作；恢复整机需将 requested=0 并确认 active=0、inhibited=0。左右侧和不同遥测模式分别保存文件。

本版测试固定机身条件下，原 RL 对可变指令的单侧输出响应；是否能正确跟踪腿长或摆角必须看实测。既有力矩层执行策略动作，本次没有新增独立拨轮腿长控制器，也不能将固定机身单腿测试等同于正常整机策略闭环表现。

## 保存与解码

VOFA+ 选择 JustFloat、**10 通道**。解码并保留原文件：

```powershell
py -3 tools/leg_response_vofa_decode.py capture.csv decoded/left-test --firmware-fingerprint <build-id> --config test-config.json
```

`build-id` 使用本次 `imcalib/Telemetry/s2r_build_info.h` 的 `S2R_SOURCE_SHA256`；配置中保留测试侧、测试开关、机器配置、零出力/投入状态、传输方式及台架说明。工具保存原始副本和 SHA256，配置保存到独立的 `configuration/` 子目录。CSV 只接受 10 列或宿主时间加 10 列，防止把旧 32 通道文件当成本布局。

输出九项主字段并附有效性：`observation_valid` 要求 bit0/1/3/4 以及递增时间；`valid` 要求全 `0x3f`、递增时间且不是换侧边界。倒退/重复时间及换侧会留下检查记录；`single_side_recording=false` 的混合侧文件需拆分采集，不能整体给出响应结论。原始二进制没有帧型，按帧尾同步仅是启发式识别，不保证能识别混入的其他协议。

此精简布局没有序号、CRC、DM 反馈力矩或逐电机反馈时间。因此它只能用于单侧腿长响应观察，不能满足“按反馈力矩与反馈时间驱动 MuJoCo”的回放准入；不得用 ch4–5（虚拟力矩）代替反馈力矩。CAN 反馈接收时间也不等于电机内部力矩生效时间。本次不据此给出“实机与模型响应一致”的结论。
